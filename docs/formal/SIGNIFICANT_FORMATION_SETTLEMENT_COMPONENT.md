# Significance-aware formation settlement

`significant-formation-settlement/0.1-candidate` — local component shape accepted,
2026-09-13. Implements the accepted significance-first retention and common formation
owner/protocol composition. The recency-only formation component remains unchanged
as an explicit control. Neither component authenticates public formation input.

Input is trusted prior significant memory, prior formation protocol, incoming qualified
source admissions, new successful formations and fresh uncredited content. Validate
the prior protocol before new admissions; prior live successes biject existing memory
with equal kind/original formation time. New memory bijects new formation results.
Replay, reused occurrence, changed prior mapping and undeclared source reject.

Fresh children cannot supply use or significance fields. Initialize use=false and the
direction set empty. Copy and preserve prior child metadata. The sole owner computes
significance-first retention over prior plus new entries under independent kind caps.
Fresh formation may commit with immediate complete loss; it still consumes its source
and acquisition identity. Derive protocol CompleteLoss from the actual owner result,
never an independently supplied survivor list. No second acquisition/loss identity.

The operation snapshots input. A private one-shot result binds resolveMemory to finish;
foreign, copied, repeated or closed results reject. No candidate state is published
by evaluation alone. Output is the paired candidate memory/protocol, requiring a later
actual scheduler commit; the component itself has no persistent mutation authority.

Frozen component controls: SF-FORM-A old significance survives later formation;
B all old bytes/use/directions preserved when no loss is required; C new credit
injection rejects; D zero capacity records successful formation plus complete loss;
E token isolation and bad prior metadata reject. Public source roles, owner patch and
complete-prefix persistence remain unqualified.
