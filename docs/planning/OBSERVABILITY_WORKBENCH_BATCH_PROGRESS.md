## Implemented contracts and behavior

`experimentRegistry.ts` declares the exact two available public seams and their
inspection capabilities. Unsupported runtime interventions, memory graphs and
matrices have explicit reasons for these profiles. It does not imply that the
remaining corpus has been adapted. Its common batch transport exposes committed
advancement and detached identity/prefix summaries, never private evaluators.

The experiment selector preserves visited Values and REASON sessions, including
their branch state, drafts, selected mode and captured checkpoints. Switching views
requests a pause at the next public committed boundary. Closing/reloading the tab
still requires exported checkpoints/reports for persistence. No UI state enters a
model, save or character evidence channel.

`batchCatalog.json` is generated by `build-workbench-batch-catalog.mjs` from the exact
125 Values and115 REASON programs. This is not an expanded Cartesian product. The
generator compares every Values frame program and REASON canonical original with
the retained plans and records the source hashes. `--check` verifies regeneration
without overwriting the catalog.

`BatchSession` executes one public adapter at a time. Limits:240 jobs,17 prefixes
per job, unique job IDs and bounded scalar metadata. Each complete prefix is checked
against its own frozen save digest. Model/run identity cannot change mid-run. The
terminal call must return false and preserve the committed view. Mismatch/invalid
horizon/worker failure remains explicit and stops the batch; later jobs remain queued.
Failed batches cannot be relabeled successful by resuming. Pause retains the same
active native run, so resume neither recreates it nor repeats/omits committed prefixes.

The browser now owns the batch through a dedicated ES module worker. Worker messages
carry detached diagnostic summaries only. Startup, pre-ready pause, concurrent command
rejection, worker errors, stale messages and disposal have explicit handling. The UI
can request a pause while the worker settles; the worker honors it at a whole instant.

Summary export includes the exact selected original programs, profile/seed settings,
all prefix identities and actual/expected save hashes, catalog source hashes, registry
version, comparison policy, capability scope and resource limits. It explicitly omits
raw traces from batch retention; the named original program can be replayed for detailed
inspection. Equality to a frozen save is not a new psychological validation or an
inactivity/removal verdict. No cross-model semantic equivalence is inferred.
