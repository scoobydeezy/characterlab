# Declared BELIEF comparison policies

2026-10-11. Workbench IN PROGRESS. `belief-contrast-inspection/0.1` defines
fourteen explicit comparisons for the forthcoming BELIEF browser inspector:
three hidden-world, three displayed-outcome, six goal-sign and two corrected-evidence
learning-law controls. This is a comparison contract qualification, not a browser
or full language qualification.

Input contrasts require one model. Model contrasts require distinct model identities
and identical original input bytes. Original programs, initial state, exact seed,
policy, both detached snapshots and comparison version are exported. Seed7 is fixed,
but these models draw no RNG; no stochastic coupling is inferred. Run/model identity,
admitted-output equality, belief-state equality and whole-save equality are distinct.
State byte comparison is licensed only for these declared controls with unchanged
state schema and named targets. Unequal prefix/instant alignment yields null equality
results rather than an inferred difference. Pair orientation and seam are checked.

The audit executes every participating original program, verifies each prefix against
the retained adapter receipt and records all terminal comparisons. It also decodes
the original calendars: hidden controls differ only in physical opportunity/outcome
fields; displayed-outcome controls differ only in reported outcome. Instants, target
identity and other frame fields stay equal. Goal and law controls retain exact inputs.
Hidden-world output/state equality, goal-independent belief and the qualified display/
law divergences are checked explicitly. NoLearning's absent state remains equal under
changed display even though admitted outputs differ; this is not missing evidence.

Three affected tests cover detached snapshots, model-control identity, rejected pairs,
unaligned prefixes and prior adapter replay behavior. Build/reference boundary and
evidence restore/research checks pass with18 conditional obligations preserved.
Source snapshots, complete comparison exports and counts are retained in
workbench-belief-comparisons-rev1/receipt.json and comparisons.json.
