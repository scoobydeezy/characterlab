## Substrate interpretation

SEM-I.1's explicit transition result identity means the resulting PerceptualReferentId
or PerceptualEventReferentId is present in the transition record. It does not require
a fresh shared-runtime transition occurrence. Existing observation/detection identities
key those transitions; newly created files advance separate observer-owned counters.
Continuation consumes no new file ordinal. Exact output key uniqueness still applies.

The accepted public attention shape already permits transports without fresh semantic
identities under its dedicated finite compiler. It does not require Campaign2's private
void-slot convention. The proposed successor likewise has no unconditional per-stage
slot. Patch-only stages retain standard patch/diff/event trace, without synthetic update
occurrences. The compiler/registration extension that enforces this is still pending.

Observation allocates one ObservationId, one detection occurrence per permitted
detection, and a current-event detection plus experience reservation iff positive.
Freeze discharges that exact reservation; it allocates nothing. World truth still has
one event and three nested truth-binding occurrences, regardless of detection denial.
Role and binding producers allocate only their actual output occurrences.

Selection allocates one existing selection occurrence. Its audit and the new selected
envelope are two top-level outputs sharing that source identity; nested selected bytes
are not another production of binding/claim occurrences. Retention reuses that identity.
Recollection allocates only actual winners, at most two. Delivery copies its earlier
concern occurrence when present; delivery's scheduler event is separately allocated.

## Local branch bounds

| Branch | Executed events | Top-level output records | Shared runtime slots |
| --- | ---: | ---: | ---: |
| Positive formation with retained content | 16 | 20 | 17 |
| Denied formation | 7 | 7 | 6 |
| Positive cue with two winners | 14 | 20 | 18 |
| Denied cue | 7 | 6 | 5 |

These bounds include one previously generated, completed delivery and the receiving
original. The number of generated local descendants is event count minus those two;
upstream delivery scheduling is excluded. They are not total MaxSettlementWork values.
Continuant/event counter increments are additional separate accounting, not runtime
slots. The positive envelopes use up to three detections and three role outputs;
the exact model cohort must establish which combinations and maxima are reachable.

With n positive detections, q actual role outputs, r indicating nonempty retention,
and w actual winners, formation has13+3r events,10+2n+q+r outputs and8+2n+q slots.
Cue has13+[w>0] events,9+2n+q+w outputs and7+2n+q+w slots. Zero-winner recollection
still executes its registered stage with zero outputs; it emits no reinforcement.
Zero retention still executes retention and emits no formation child.
