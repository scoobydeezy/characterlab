## Do not invent an efficacy belief to connect the options

The current forecast is not action-conditioned. Task content cannot therefore say
that the character knows "action A raises the reading" just because a world-effect
table says so. Two possible bridges remain under review:

* A genuine action-expectation learning seam from permitted self-attempt and observed
  consequences, with fallible attribution and explicit source restrictions.
* An explicitly adopted **procedural task plan** in initial prospective context.
  It specifies what to try, not the probability or causal effect of doing so.
  Candidate construction follows the plan's instruction semantics while world
  execution remains independent. A task still need not be achieved by that attempt.

The second is potentially thinner for Campaign2's first intact event and permits
reuse of the historical prescribed fulfillingAction control without claiming learned
efficacy. It must be a registered plan/context contract, not a hardcoded mapping in
the option builder. Initial adopted context is S0, not a hand-authored transient
Reason, appraisal or intent. No option/plan code is authorized by this sketch.

## Keep the physical and cognitive time boundary honest

The present diagnostic variable is an adapted authored reference, not a full
physiological body meter. An action cannot directly write D merely to make a task
succeed. Only ADAPT's sole authority may change it from actual admitted exposure.
Because that write commits at140, a probe earlier in the same instant cannot observe
the new D. The candidate cycle must use a later observation when that is the causal
quantity it intends to test. Do not retime the probe or fabricate immediate bodily
change to shorten the scenario.

A future two-effect world model may require distinct actual exposure referents/rules.
Those are new model facts and producer/profile work, not a change to accepted ADAPT
arithmetic or an instruction for a character to access the truth-side exposure count.
The exact first effect table remains unchosen here.

## The identity loop must actually change a later boundary

Two identical commitment-channel reasons plus an identity modifier that boosts both
equally may leave their contest unchanged. Merely storing an identity record would
not witness the retained loop. Before freezing the scene, require a counterfactual
where a legitimately qualifying, frozen expression creates standing identity that
matches a future reason differently and moves settled/unresolved choice.

Do not manufacture that difference with a displayed trait bonus, a new independent
identity die, or an arbitrary task-ID magnitude. Exact expression interpretation,
authorship qualification, referent/semantic matching and standing modification must
be formalized from the retained Phase2.9–2.97 mechanisms. If two task types cannot
support that witness honestly, revise the scene before implementation.
