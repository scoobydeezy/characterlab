# Reachable cognitive settlement branches

Status: DRAFT; proposed first-profile stage grammar. No runtime or allocation change.
Notation A/P/S/D below refers to the predecessor's complete admitted ADAPT,
prediction-application, task-measurement and task-deadline branches, not generic events.
Memory formation remains paired with the admitted prediction branch as already required.
I is the single new identity-application child, including authentic qualification rejection.

## Source exclusivity gives a small grammar

The first profile admits original diagnostic probes and original deliberation
opportunities, never original authored adaptation facts. A probe instant cannot also
contain a deliberation opportunity. Other existing generated read/recall events may
coexist because they produce no physical action or140 write. Deadlines may coexist
with either original source. The model forbids adding arbitrary generated physical
sources through original input or a registration callback.

The exact new reachable classes are:

| Instant class | Required140 participants |
|---|---|
|Diagnostic probe|The predecessor's P+S+optionalD branch, including its exact memory pairing and suppression/padding rules. NoI and no protocol A.|
|Deliberation with Chosen result|The complete protocol A branch plus exactly oneI, plus any dueD.|
|Deliberation with NoOptions/NoActiveReasons|Only dueD, if any. NoA, noI.|
|Deadline-only|Exactly its dueD branch.|
|Read/recall-only|No new140 participant; preserve any independent dueD.|

This does not authorize an arbitrary P+A+I combination. A new physical/coexistence
profile would need a successor grammar. Nor does I-only become reachable merely
because the component can process it: a valid chosen action always reaches an actual
outcome and emits one307 even when completed count0. A failure before that completion
aborts the whole instant rather than committing its identity branch alone.

## Complete preparation before prior reads

At140 authenticate every scheduled participant against the live generated graph and
the applicable row. Count/padding/cardinality failures precede all participating
prior reads. A forged missingI, duplicateI, missingA or unexpectedP cannot be hidden
by a no-write qualification result or a zero-count adaptation result.

Resolve all source subjects and potential target keys using captured admitted inputs
and exact declared accessors. Perform complete target intersection checks, then seal
preflight. Only after the seal may each participant receive its B0 prior. Even a
rejected I remains a required executed participant, but resolves no write/read target.
One identity event per cognitive source is checked independently of target collisions.

Identity candidate writes only its own new leaf. ADAPT retains its exact root/field
ownership and domain/reference checks. Task lifecycle retains its exact373 field1
write path, and the added immutable plan field cannot enter either patch. Memory and
prediction pairing stay unchanged on probe rows. No whole-root overwrite can replace
the mixed prospective family or swallow identity into an existing authority.

The joined prepareCommit checks exact execution completion, child binding closure,
candidate invariants, quiescent task expiry and all private pending facts. Any failure,
including the final trace/draw projection, aborts the complete instant. Publish patches,
occurrence/event allocators, outputs, trace and used random addresses together.

## Required negative controls

Freeze as proposed CS-A..J, NOT PASSED: missing identity; extra identity; missing
actual-fact branch; forbidden probe/protocol mixture; zero-count does not removeA;
qualification rejection does not removeI; all source/target checks precede priors;
immutable plan preservation; post-draw/post-identity-candidate/final-trace failure
restores every state family and private association; full-prefix replay reconstructs
the identical reachable branch and queue. Include an actual due-deadline overlap
with a remaining live task, not only component-constructed D events.

## Outstanding numeric work bound

The model must derive event/child/runtime-output counts for each row and each valid
control combination, including existing readouts/recalls and simultaneous deadlines.
The table closes semantic reachability, not numeric accounting. Count analysis also
includes at most two reason faces plus one tie draw, each at most three SHA candidates;
those candidate computations are not scheduler events or new runtime occurrences.
Do not inflate an old local probe budget or declare a round maxWork value without
the actual joined graph count and boundary tests.
