# Retained attribution use component

2026-09-12. `retained-attribution-use-component/0.1-candidate`.
Primary-agent component shape acceptance implements the user's retained-operand
consumer ruling. No public source/record/allocation acceptance is implied.

The trusted coordinator supplies a detached committed memory snapshot, evaluation
instant, an admitted child read set, four trial bindings, and a trusted projection
adapter. A retained binding identifies an existing acquisition/child and view index;
a detached binding supplies a value without memory-use credit. The adapter is part
of the trusted fixture substrate, not caller-authenticated public evidence. It must
decode only the supplied retained view. Public subject, role, trial ordering and
observer-safe projection authentication require the whole successor source contract.

All bindings are structurally validated and all projected values are checked against
contrastive-attribution-component/0.1-candidate before evaluation. This validation
earns no credit. Retained addresses must be admitted, extant and acquired strictly
before the evaluation instant; a view must exist. Validation freezes projected motion
and exact interval data. No observation/archive resolver is accepted as a memory read.

Semantic evaluation proceeds in supplied trial order. For each trial: inspect motion,
then before interval, then after interval. Missing or ineligible motion stops; missing
interval stops. Once all complete, compare before intervals to the first in trial
order, check two Stroke/two Stationary, then use the existing exact contrast rule.
This fixes a bounded evaluation strategy while preserving the old verdict for every
admissible trial tuple. Unread bound values are not consumed operands. The semantic
read hook records only distinct retained child addresses actually evaluated, even
when multiple views of that child are used. Supported needs the full four-trial basis.
Unavailable is a completed assessment, not transaction failure.

Evaluation returns a frozen opaque session-local token. Only the originating session
can finish it once. Finishing derives a candidate result and child-local protection
from the actual semantic read set; it does not commit state. Trusted scheduler commit
must atomically accept both, or neither. Closing the session disables all tokens.
No persistent result occurrence is allocated by this component. Candidate display
has no feedback path. A subsequent retention instant may read committed protection;
same-instant retention/new formation use is outside this first contract.

The public contract still needs governed result identity, subject/read authority,
projection provenance, transaction registration, canonical persistence and later
retention scheduling. Component ordinals and admission sets are trusted fixtures.
This contract cannot turn caller-supplied memory bytes into public use authority.
