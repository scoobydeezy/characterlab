# Explicit requested source sampling

`requested-source-sampling-component/0.1-candidate`, 2026-09-13.
LOCAL DISPOSITION — no owner ruling required.

The existing body, panel and display sources are sampled only when explicitly
requested. A request contains exactly bodyChannels (null or1..9 actual channel
names), panel Boolean and visual Boolean; at least one surface is requested.
This is a component request, not a public canonical record or model admission.

Unrequested surfaces are absent from the returned product and are never called.
A requested unavailable surface still returns its actual observation header and
unavailable sample. It cannot disclose why observation failed. Present zero values
remain present. Identity allocation occurs once per requested observation, using
the enclosing allocator, with uniqueness checked across modalities in this call.
No duplicate local occurrence namespace or persistent sampling history is created.

This preparation owns no perception state, experience reservation, selection,
cue, acquisition or learning. The existing combined opportunity delegates its
all-three physical sampling to this function and retains the original SEM and
perception transaction. Other request combinations require their appropriate
accepted downstream orchestration; absence here is not an instruction to clear an
unsampled perception context. Failed allocator reservations remain the enclosing
runtime transaction's rollback obligation.

Preserved comparison: coupling visual opportunities to mandatory body sampling
must be an explicit different request schedule, never an implicit source read.
No psychological or public registration claim follows from component tests.
