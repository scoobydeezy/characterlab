# Cognitive operand capability review

Status: internal design review, DRAFT. This is an implementation constraint for the
new profile, not a claim the new capabilities or tests already exist.

The full committed registry necessarily contains protocol execution permission and
regulatory definitions. Passing that whole registry or compiled model into every
psychological transformer would make a ReadDomain={} declaration insufficient: a
handler could read truth-side configuration without touching a state accessor.
Likewise a raw AuthoritativeState object exposes more than the promised workspace
or identity projection. The new handler boundary must enforce the smaller operands.

## Required partition

* Workspace receives its authenticated opportunity, exact agenda/task definitions,
  accepted IDN subject projection and capability-limited task/prediction reads.
* Appraisal, concern and motive receive their actual predecessor output and exact
  immutable calibration/spec operands only.
* Candidate construction receives its exact motive context, selected-task plan reads
  and matching protocol instruction definitions. It receives requested operation
  count only as procedural definition content, never execution permission/outcome.
* Raw-signal construction receives actual candidate context and the one identity
  history projection. The pure coverage, meaning and dice functions receive only
  validated immutable mathematical operands.
* Arbitration receives the exact reason context, two threshold values and addressed
  draw capability. It cannot choose another model's seed, inspect raw run inputs or
  substitute an external action. Draw capability checks the current root/purpose/
  subject bindings and span, not merely an arbitrary RandomAddress-shaped object.
* Expression/qualification receives frozen chosen context and the exact bounded
  qualifier definition. It has no current state or world-outcome lookup.
* Plan/attempt receives its actual chosen source and selected instruction. Only
  Execution receives its own permission operand. Its two bridges receive exactly
  the authenticated outcome projection appropriate to their separate lanes.
* Identity application receives the qualified source and one prepared B0 prior,
  then returns its separately owned candidate patch. It cannot publish state directly.

The outer trusted runtime may hold the complete compiler/source/state for scheduling,
validation and persistence, but these are not psychological handler operands. No
closure passed into a handler may offer generic lookup, full registry bytes, state
entries, all outputs or a trace archive as an indirect escape. Read results are detached
canonical values, with private source/event association checked before use.

## Adversarial checks required

Vary execution permission and unrelated REG/model truth while holding a specific
handler's permitted operands fixed. Its output must remain byte-identical, excluding
only intentionally distinct enclosing model/trace identities. Check the psychological
output itself, not an omnibus run digest. Conversely changing the actual captured
forecast/goal/plan/history operand must affect only its defined downstream mechanism.

Inject a lookalike event/source, an older occurrence, another holder's key, an altered
definition reference, extra requested state path and a callback-bearing public object.
All must fail at admission without obtaining an unauthorized value. Instrument actual
read capabilities so missing or phantom read traces fail. The full public factory
remains data-only; no handler/compiler/accessor function is a supported input.

These constraints preserve distinct truth and character provenance even though the
researcher may inspect both in the public trace. Research inspection access is not
a character-model capability. Existing FCT qualifications do not automatically pass
these new source partitions; the successor needs its own executed crosswalk.
