## Definition of assembled (all required)

1. One model definition per configuration, one authoritative state, one scheduler,
   one ordered trace, one run identity and one deterministic checkpoint. Parameters
   and law variants legitimately change model identity. Variants are fixed for a run.
2. Shared concepts have shared state ownership, following Architecture section 5.
   Each persistent state family has one mutation authority. Different operations may
   feed that authority; different operations do not automatically need different state.
3. The accepted phase order and both perception lanes apply. Phase 150 is a
   non-schedulable settlement sentinel. Not every event executes every phase.
4. Scenarios provide initial conditions, world events and permitted interventions to
   the same mechanisms. No scenario-name switch may select a replacement psychological
   pipeline. Wrapping isolated factories in one scheduler/save does not qualify.
5. Every configuration satisfying declared domains AND cross-field, reference,
   capacity and state invariants is admissible without a frozen-fixture allowlist.
   Invalid configurations receive specific rejection reasons. Test at least one valid
   non-preset configuration; do not merely enlarge the frozen list.
6. At least one actual loop traverses experience/perception, belief and appraisal,
   motivation, reasons, decision, expression, execution, perceived outcome and learning,
   with retained learning affecting a later decision. No authored psychological
   intermediate may stand in for a missing causal producer.
7. Demonstrate retained experience combining with a later bodily or social condition
   to change appraisal/decision. A controlled connection/state comparison must show
   the effect. Stage coverage alone is insufficient. Identity, habit, skill and
   relationship updates occur under their legitimate conditions, not on every event.
8. All 15 retained research families and 132 enumerated clauses remain in scope,
   alongside the 21 corpus members and their required comparisons. Intermediate
   subsets are progress only. The whole model must exercise applicable connections;
   the single interaction witness is a minimum, not a substitute for family coverage.
9. The pinned baseline replays on the assembled character with accepted explanations
   of differences. No unresolved integration defect, law conflict, missing required
   phenomenon or unclassified difference remains in that baseline at completion.

## Replay and interpretation

Define compared projections, semantic correspondence, seeds/input differences and RNG
coupling before execution. Same seed alone does not prove cross-model draw coupling.
Preserve uncertainty, observer boundaries and evaluation-time reasons in comparisons.
Use the following classification at the individual finding/requirement level:

- **Equivalent:** the declared relevant behavior AND meaning agree.
- **Interaction:** name the causal edge, show the consumed state and a controlled
  comparison, and establish that the required phenomenon/invariants still hold.
- **Defect:** fix the integration bug; a classification is not acceptance.
- **Law conflict:** obtain a ruling and implement its resolution; do not waive coverage.

An unclassified difference blocks the affected milestone, not unrelated read-only work.
Do not retune the comparator after seeing results to manufacture a pass. Changes to
comparison meaning or required scope need an owner amendment. Ordinary test bugs may
be corrected transparently while retaining the original failure and expected meaning.

## Anti-bloat rules (operational limits, not aspirational advice)

- One active implementation milestone and one long-running validation job at a time.
  No speculative parallel audit tracks. Finish a milestone before extending its scope.
- Before coding, put a milestone card in CURRENT.md: at most 3 observable capabilities,
  baseline IDs, touched contracts/files, comparison, exact checks with failure risks,
  runtime/output budgets, and a binary done condition. No empty budget placeholders.
- If the milestone is expected to touch more than 12 production/test files, split it
  before coding. If it exceeds that during work, checkpoint and re-plan; do not quietly
  expand. This is a work-package limit, never permission to shrink final coverage.
- Default new evidence budget: 20 files / 5 MiB per milestone. Retain sufficient raw
  observations and counterexamples for the claim; if they cannot fit, request a specific
  budget amendment before executing. Never discard material evidence to meet the cap.
- Use Git revisions and original fixture references for source identity. No recursive
  source copies, build snapshots, accumulating catalog versions, per-attempt evidence
  directories, source holds or browser-tab retention. Keep existing frozen evidence intact.
- Required checks: affected functional tests, repeat determinism, checkpoint continuation,
  relevant ordering/ownership/epistemic negative controls, and the affected pinned replay.
  Run existing type/boundary/research checks as applicable. Complete full pinned replay
  once for the final candidate; rerun only changes with a stated invalidation reason.
- No browser execution, exhaustive browser parity, every-prefix whole-corpus parity,
  verifier-of-verifier chain, or new validation framework. Each additional check must
  name a concrete undetected failure risk and why a smaller existing check cannot catch it.
- On passing the milestone's checks, stop adding tests and report the outcome. New
  failures or source changes can justify targeted reruns; habit and counter growth cannot.
- Five revisions of an artifact without changing its disposition: stop and ask whether
  the artifact is necessary. Stop earlier on two attempts with the same unchanged blocker.
  Stop at the declared runtime/output budget; record incomplete, never infer success.
- Planning document budget: AGENTS.md <=120 lines, CURRENT.md <=80, this order <=250.
  One baseline manifest and one reconciliation register. Git holds history; no REV chains,
  duplicated ledgers, or new dashboards. One compact result per milestone, linked from
  CURRENT.md; preserve meaningful failures without duplicating the entire source universe.
- Status begins with what the character can now do and what remains. Technical evidence
  follows. Neither file counts nor audit counts constitute feature progress.
