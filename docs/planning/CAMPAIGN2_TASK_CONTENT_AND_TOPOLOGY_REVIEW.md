2026-09-09. Agent adversarial review of task-commitment/0.1-draft.
**Components accepted in direction only; whole shape and allocation remain open.**
No existing CONTENT/VAL/REG/ADAPT contract is relabelled or reopened.

## 1. Concrete authored instances without another identity family

Use one170/1 governed content record per concrete task instance. StableId is the
existing GovernedContentDefinitionId/1038; SemanticKind is the proposed exact
SemanticKindId/1004 member semantic-kind/task-commitment. TaskReferent is exactly
SemanticReferentId/1002(AuthoredContentOriginId/1037(complete StableId)).

Recurrences have different StableIds. Neither stakeholder nor task prototype is
the instance identity. This first profile has a finite authored instance domain;
runtime-created adoption/recurrence remains unadmitted. No runtime origin is forged
in S0, and no new TaskInstanceId namespace or identity registry is needed.

Character qualification is unchanged: an authored task referent fails the existing
character-kind predicate. A new separately declared task-kind predicate can qualify
a TaskReferent by exact authored origin and committed content kind. It must not be
made an alternative successful branch of validator/character-qualification.

## 2. One spec authority; no executable prose or psychological content

Propose a TaskCommitmentSpec registry entry containing exactly:

| Field | Grammar and authority |

| HolderContentId | GovernedContentDefinitionId; resolves to character-kind content |
| PredictionDefinitionId | Existing RegistryDefinitionId; resolves to the admitted prediction criterion/channel domain |
| DesiredMinimum | Exact rational inside that prediction domain |
| DesiredMaximum | Exact rational, DesiredMinimum≤DesiredMaximum |
| ActiveFrom | Exact simulation instant≥0 |
| Deadline | Exact simulation instant>ActiveFrom |

A concrete task content record maps to exactly one spec through a closed receiving
profile. The final content-kind grammar must choose the precise170 field positions
for that reference; references, lifecycle declaration and semantic mapping must all
resolve to the same committed spec, not duplicate the criterion/window themselves.
The spec can serve only its declared concrete content instance in this version;
two recurrences may have equal criterion but independently declared windows/specs.

The spec contains no interpretation, urgency, concern, pressure, reward, success
probability, action efficacy or identity conclusion. A separate motive/calibration
registry may define the reference mechanism's common coefficients, but content
cannot inject a raw psychological result. Authored lifecycle and goal facts are
permitted by CONTENT_GOVERNANCE; authored psychological conclusions are not.

Reuse329/1 for the content-kind declaration and330/1 for the exact task-role
predicate if their existing field grammar is sufficient. Their **new exact
specialization versions and member identities** must commit the additional meaning.
Do not pretend content-kind/0.1's character-only supported domain already admits it.

The real compiler currently assumes every content record is a Character. In
particular REG's implementation enumerates all current content records, because
that is true of every previously admitted model. A successor compiler must supply
the actual qualified-character image, or explicitly update that implementation to
filter by the accepted Character predicate. It must not demand REG anchors for
task records or weaken Character qualification. Existing one-kind source bytes and
their earlier rejection controls remain unchanged.

## 3. Prospective control is not a synthetic appetite or mislabeled learning

The ten-family ADAPT registry is explicitly exhaustive **for its initial model**.
Its route membership is independent from mutation ownership and admission. The
architecture separately requires prospective goals/commitments; they are not one
of those ten learned/adaptation families. Hiding their state in belief, memory or
identity would merge separate authorities without a reduction verdict.

Propose a successor topology with the ten unchanged rows plus one
prospective-commitments family. Assign a separately declared logical route,
route/prospective-control, using the existing logical route identity family. The
new member's semantics require an explicit extension; its namespace's historical
LearningRouteId label does not confer admission or make clock control into learning.

The new prospective family has one physical root and one sole authority. Its
explicit route does not authorize an automatic-adaptation transition to write it.
Conversely a prospective control transition cannot write any of the ten other
families merely because it consumed character-relative evidence. Record the full
eleven-family route/root/owner coverage before implementation.

342 may be explicitly admitted as an observer-safe prospective satisfaction input
without becoming AutomaticAdaptationInput or a universal lifecycle credential.
Its M1 producer remains on character-learning. This is a new, named downstream
consumer of the same evidence, not an implicit cross-route cast. Deadline control
has its own authenticated clock/initial-instance source and never manufactures a
measurement-learning record to disguise its origin.

A prospective trace or terminal output must be included in its own output closure.
The old character-learning and automatic-adaptation closures retain their previous
members. Future phenomenon comparisons must additionally preserve/probe prospective
state explicitly; a third route is not a loophole to omit it from causal tests.

## 4. Initial context and lifecycle scope

The first successor may initialize exactly its declared finite task keys as Open.
That is explicit initial adopted context under S0, not a claim that the runtime
performed adoption. No caller-authored appraisal, pressure, Reason or intent is an
input intermediate. All of those must be generated by their subsequent transitions.

The exact immutable window gives dormant/active/deadline eligibility. Open is not
synonymous with currently active. Physical DeadlineMissed commits at the deadline's
140 stage; earlier40/60 eligibility already excludes T≥Deadline.

PerceivedSatisfied and DeadlineMissed are distinct retained terminal states. This
version does not claim Relinquished, Cancelled or socially Fulfilled by naming them
in an enum. Those future causes require their own evidence and control transitions.
The historical live-list test is compared on live pressure and recurrence identity,
not on unimplemented social attribution.
